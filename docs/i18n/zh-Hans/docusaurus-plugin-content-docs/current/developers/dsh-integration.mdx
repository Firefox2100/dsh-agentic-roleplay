每个角色扮演会话映射到 ID 为 `session-<角色扮演 UUID>` 的真实 DSH 会话。所有角色扮演对话共享以数据根目录为工作目录的 DSH 工作区，而具体会话目录通过 UUID 解析。

开场消息在 DSH 控制器接管前作为完整第一回合持久化。若在实时智能体构建后追加，会使循环缓存的最后回合状态不一致。

大多数功能使用公开 Cordis 与 DSH 服务。角色和记录员子智能体是有意的例外：并行角色需要相同工具名对应不同私有结果，因此使用 DSH 组合辅助接口。契约测试将其约束在 DSH 0.2.x。

升级 DSH 前应运行契约测试，并验证子智能体、开场回合、重新打开、回退、分支、对话停用、浏览器插槽和共享世界编辑器。

## 浏览器如何得知故事变了

对话记录跟随 DSH 自己的会话事件。屏幕上的其它东西——条带、界面页签、建议、日志——显示的是会话 SQLite 里的故事状态，DSH 的会话投影搬不动它：投影只折叠会话日志，而故事不在日志里。

所以浏览器通过 `/roleplay-api` 读这些值，并在这些时候重新读：

- 有理由时：回合开始或结束（输入区、界面包自己的页签、右侧栏里的包页面都用 `useSession(state => state.running)`），或显示该值的页签被打开；
- 该值在屏幕上且页面可见时按定时器读（`src/client/visibility.ts` 的 `pageVisible()`）；
- 页面在后台时不读：隐藏的页面跳过请求；用 timeout 链排队的轮询会保留尝试次数，等玩家回来；
- 页面回到前台时立刻读一次：原本会在后台轮询的值通过 `onPageVisible()` 再读一次，所以留在后台的页签不会让玩家等到下一个 tick。

当前间隔：界面包 10 秒、玩家视图 5 秒、建议 2 秒（只在第一次回答到来前；角色自行发出的消息为 30 秒）、反思 4 秒、同步 2 秒、试玩 2 秒、还有图片在描述的画廊 3 秒、参考页 8 秒、还在生成的场景图 1.5 秒。这些是等待的上界，不是回合信号的替代：回合一变就立刻再读一次。
