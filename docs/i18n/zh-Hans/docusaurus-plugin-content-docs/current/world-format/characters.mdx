---
title: 角色
---

每个角色位于 `characters/<folder>/character.json`。核心字段包括 ID、名称与别名、`playable` 或 `npc` 角色、`person` 或 `group` 类型，以及 `principal`、`supporting`、`background` 层级。可扮演角色必须是个人且不能是背景角色。

简介、性格、背景、外观和说话方式承担不同提示用途，不应合并成一段传记。年龄、性别和代词都是可选信息。其他角色、游戏主持人和记录员读到某个角色时，名字后会带上代词（只给了性别时用性别），这样叙述和记录不必让模型去猜；两者都不写则既不显示也不猜测。

`start.public_state` 是可观察状态，`activity` 是实际正在做的事，`inner_state` 是私密想法。初始位置、情绪、意图、日程、阵营成员关系、物品和变量值也属于初始状态。

`relationships` 是该角色指向另一角色的单向关系；反向必须单独定义。`knowledge` 显式列出已知地点、物品、有方向的出口和设定资料；没有记录就是不知道。

`routine` 由按顺序匹配的时间窗组成，可指定 `days`、`on`、起止时间、活动、地点、特征、是否可中断和 `sleep`。结束早于开始表示跨越午夜。

`days` 使用 `mon` 到 `sun` 表示星期。`on` 使用共用的[日期标记格式](./calendar)，可进一步限定日期、月份、季节、节日和排除项。两者同时存在时必须同时匹配。例如，下面的工作日日程会在建城纪念日暂停：

```json
{
  "days": ["mon", "tue", "wed", "thu", "fri"],
  "on": ["!holiday:founders-day"],
  "from": "08:00",
  "to": "16:00",
  "activity": "在档案馆工作",
  "location": "archive"
}
```

`sleep: true` 标记角色在其中睡觉的时间窗：夜间睡眠、小睡。角色只有在时间窗指定的地点（没有指定则不限）、且没有被叫醒时，才算在这个时间窗里睡着。睡着的角色不参与故事，除非玩家的行为把它叫醒；它不会给玩家写消息，可以用 `/dream` 进入它的梦。玩家自己的角色没有日程，也永远不会按日程睡觉，无论文件里怎么写：它属于玩家。“角色按各自的日程生活”设置关闭的故事里，没有人睡觉。

故事对角色造成的影响优先于日程。被带去别处、被派去办事或被叫醒的角色会暂时离开日程，直到游戏主持人说的那么久过去，没有说时则到它的一天下一次变化，然后按此时在日程中所处的位置继续。
