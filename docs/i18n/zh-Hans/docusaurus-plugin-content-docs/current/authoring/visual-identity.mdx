---
title: 视觉身份
---

角色、地点、物品和阵营都可以拥有视觉身份：

- **description：** 稳定且可见的事实；
- **tags：** 帮助图片模型保持一致的稳定特征；
- **negative tags：** 图片必须避免的特征；
- **global ID：** 可选的跨世界共享身份；
- **version：** 身份发生变化时更新的版本。

表情、姿势、临时服装、光照、损伤和周围环境不属于规范身份，应放进场景的临时描述。

有效的身份应说明：另一位画师在不同构图中仍能认出同一主体所需的事实。优先使用具体视觉特征，不要只写风格形容词：

```json
{
  "description": "一位三十岁出头的女性，灰色眼睛，深色波浪长发，左眉有一道细疤。",
  "tags": ["灰色眼睛", "深色波浪长发", "左眉细疤"],
  "negative_tags": ["金发", "蓝色眼睛"],
  "version": 1
}
```

不必在三个字段中重复所有描述。自然语言说明身份，标签强化简短的正向锚点，负面标签则防止反复出现代价较高的错误。

## 参考图

规范图片固定命名为 `reference.png`，重新生成会替换该文件。有全局 ID 时存入 `images/global/<id>/`，否则按实体类型和本地 ID 存储。

只有多个作者实体确实代表跨世界或副本的同一视觉主体时，才使用全局 ID。名称相同并不足够：两个互不相关、都叫 Mara 的角色不应共享身份。

上传 PNG 肖像可以代替生成。上传文件会成为当前参考图并记录来源。如果重新生成后可能需要恢复，请把原始素材另行保存。

## 场景图

场景图把稳定身份与当前外观和这一刻的构图结合。提供方支持时可以附带参考图进行条件生成。场景文件在 `images/scenes/` 下按时间线节点编号，永不覆盖。

元数据与图片一起保存，必要时使用伴随文件。文件系统始终是权威来源，用户可以直接管理媒体。

## 身份版本

稳定视觉事实变化时增加 `version`，例如重新设计的制服、永久疤痕、重建后的物品或阵营的新徽记。表情、天气、临时受伤或镜头角度变化不需要增加版本。

版本变化不会重新生成既有场景图；它们仍是早期时刻的记录。应生成或上传新参考图，让未来场景使用修改后的身份。

## 保持场景一致

- 让稳定身份独立于姿势与环境。
- 重要物品与地点应拥有自己的身份，不要全部塞进角色描述。
- 临时服装、状态和活动应来自当前会话状态。
- 选择少量有辨识度的特征，避免堆砌泛泛的美感或质量词。
- 图片不一致时检查图库元数据，其中会显示实际使用的身份与版本。
