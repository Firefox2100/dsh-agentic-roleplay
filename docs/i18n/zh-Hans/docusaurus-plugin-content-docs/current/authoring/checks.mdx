---
title: 检查世界
---

一个世界即使格式正确，也可能有别的问题：角色设定只有一行、导入漏掉了卡片中的事实，或者两个数值追踪的是同一件事。**检查套件**用来查找这些问题。你可以在世界的创作聊天里输入命令来运行它，创作助手也能通过工具调用。每次角色卡导入和更新都会自动运行快速检查。

检查不会修改世界的创作内容，只会把最近一次结果保存在 `.checks/results.json`。助手会用平常的编辑工具修复发现的问题，每次修改仍会照常先征得你的同意。

## 命令

在世界的创作聊天里输入：

| 命令 | 运行内容 |
|---|---|
| `/check` 或 `/check-all` | 三个检查包全部运行 |
| `/check-world` | 一致性检查包 |
| `/check-card` | 对照检查包（需要这个世界导入时用的角色卡） |
| `/check-quality` | 质量检查包 |

命令后面加的内容会交给助手。加上 **deep**（`/check-quality deep`）会让模型参与；不加时只运行由程序判定的检查，当快速检查的结果显示世界内容单薄时，助手也会自己打开 deep。助手会运行检查、阅读发现的问题、修正明显有误之处、对需要做选择的先询问你，然后再运行同一项检查加以确认，最后告诉你发现了什么、改了什么、还剩什么。

## 三个检查包

**一致性**由程序判定，成本很低，始终可以运行：

- `world-valid`：每个文件都能读取，每处指向某样东西的引用都指向确实存在的东西，与开始故事时的检查完全一样。它会指出世界中第一个有问题的部分，所以修好之后可能会显示下一部分的问题。
- `world-graph`：无人能到达或离开的地点、没有返程的通路、钥匙不存在的锁、同名的角色、地点或物品。
- `duplicate-values`：对同样的对象含义相同的追踪数值（`hp` 和 `health`）。保留哪一个需要选择，所以这条发现只列出两者，不做改动。
- `name-clashes`：某个别名恰好是另一个角色的名字，两个组织或两个背景条目同名。
- `world-prompts`：世界自带的提示词必须是产品里有的提示词、不能为空，并且只使用该提示词被提供的变量。

**对照**把世界与它导入时用的角色卡（保存在世界的 `.import` 文件夹里）对照，或与等待更新这个世界的较新角色卡对照（`/check-card` 和 `check_card` 工具可以用 `version: new`）：

- `card-coverage`：导入为世界读取的每个片段都变成了某样东西。没有任何内容来自的片段，是被悄悄丢掉或略去了。
- `card-names`：世界里的每个角色、地点、组织和物品，在卡里的某处都有出现。如果大多数名字都找不到，它只会说一次：世界很可能用的语言与卡不同。
- `card-numbers`：片段中给出的数字（年龄、年份、数量）出现在由它生成的内容里。
- `card-update`：有较新的卡等待时，新卡改动或新增了、而世界里还没有写到的内容，以及只由已被删除的片段生成的内容。
- `card-fidelity`（deep）：对由卡生成的每份文档，模型列出卡里陈述而文档丢失的事实，以及文档陈述而卡里没有给出的事实。每条事实都附带一段引文，引文如果不在它声称出自的文本里就会被拒绝。一次运行至多对比 40 份文档，先比对来源最多的，并说明漏掉了多少。

**质量**根据现有内容，判断这个世界是否足以游玩：

- `quality-cast`：有人可以扮演，重要的角色不止有简介和说话方式，没有两个角色共用同一段简介。
- `quality-places`：没有描述、或只有一行描述且没有特征的地点。
- `quality-world`：简介、标签和开场。
- `sheet-playable`（deep）：对每个主要和次要角色，设定是否说明了他是谁、怎么说话、想要什么。导入设置选用了[决策模型](../playing/settings)、并且它有把握时，可以由决策模型回答；它没有把握的交给语言模型。
- `world-gaps`（deep）：模型阅读世界的概要，指出要玩得好还缺什么：无事可做的地点、无人承担的冲突。每个缺口都指明它涉及的角色、地点或条目，以及补上什么。它不会用来源里没有的内容去填补缺口。

每条发现都有严重程度（**error**、**warning** 或 **info**）、代码、位置、说明，以及（修法明确时的）提示。error 是需要修复的；warning 是需要去看的线索；info 只需一提。

## 导入时会做什么

角色卡导入、无模型导入以及从新卡更新，都会对世界现在所依据的角色卡运行全部由程序判定的检查，并保存结果。审阅导入的助手会读到这些发现，并决定是否值得运行 deep 检查：卡很长、很多片段被改写成了背景条目、或者快速检查显示有事实丢失或角色单薄时。从新卡更新快要完成时，助手会在调用 `card_update_finish` 之前，用 `version: new` 运行 `check_card`。

## 结果保存在哪里

每项检查最近一次的发现保存在世界的 `.checks/results.json`。下一次运行会说明有多少条是新的、哪些已经消失。与 `.import` 一样，这个文件夹属于创作状态：它是点开头的文件夹，不属于你发布的世界，翻译也不会复制它。可以随时删除，下一次运行会从头开始。

助手可用的工具是 `check_world`、`check_card`、`check_quality` 和 `check_list`；`check_list` 会列出每项检查属于哪个检查包、由程序还是模型判定，以及它需要什么。
