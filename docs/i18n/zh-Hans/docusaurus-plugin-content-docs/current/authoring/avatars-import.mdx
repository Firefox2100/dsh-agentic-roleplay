## 可复用化身

玩家化身位于角色扮演根目录，而不属于某个世界。在**化身**页创建和编辑。可以把化身复制进世界成为可扮演角色，也可以只在开始会话时带入，不改变世界。

复制品彼此独立。之后修改原化身不会重写世界或已有会话。

可复用化身适合保存玩家角色的稳定部分：姓名、代词、外观、声音、性格和可移植背景。世界专属关系、当地知识、物品与起始位置应放在世界或会话副本中，避免角色在不同设定之间携带不可能拥有的知识。

### 复制到世界还是只加入会话？

- 当化身属于世界设计好的固定角色，并应出现在每个未来会话中时，复制到**世界**。
- 当某位玩家只想把它带入本次游玩，而不改变世界时，添加到**新会话**。
- 设定需要本地变体时，编辑复制出来的角色；可复用来源保持不变。

## 角色卡

导入器接受支持的角色卡，提取文字与图片，再由导入智能体映射到原生角色格式。可以安全获取并验证的图片会进入世界图库。

导入后必须检查数据。角色卡很少像原生模型那样明确区分公开事实、私密状态、稳定外观、起始行动和长期目标。

重点检查：

- 哪些事实可以公开，哪些应放入 `inner_state` 或显式知识；
- 哪些文字是聊天机器人回复指令，而不是世界中的人物特征；
- 示例对话是否应转换成说话风格，而不是当前对白；
- 哪些外观足够稳定，可以进入视觉身份；
- 角色目标和起始活动是否能让它在开场时有事可做；
- 导入姓名或 ID 是否与现有角色冲突。

导入结果是一份草稿，不是持续同步层。转换完成后，原生角色文件与复制的图片成为权威内容；修改原始角色卡不会更新它们。

导入上限、并发、推理强度、token 预算和温度在核心插件中配置。网络图片只有在地址和响应类型都通过验证后才会获取。

若角色卡过大或含糊，请把来源缩减为真正定义角色的事实，再通过编辑器补充设定专属内容。动机清晰的精炼角色，比充满重复示例和指令的长卡更适合运行时使用。
