---
title: 创作助手
---

在世界编辑器选择**创作世界**。DSH 会在**编辑世界卡**项目中打开以世界命名的对话，并使用专用创作智能体，而不是通用或角色扮演预设。

助手可以列出和读取世界元素、检查链接与关系，并提出创建、更新或删除。修改工具写入的正是手工编辑器使用的同一组文件。

助手还能读取和写入世界的**触发器**（世界自行发生的事）：`list_world_triggers` 和 `get_world_trigger` 用于读取，`write_world_trigger` 和 `delete_world_trigger` 按键创建、替换和删除。触发器会像故事开始时那样被读取，格式有误或提到世界里没有的角色、地点、物品、变量或触发器时，会连同全部问题一起被拒绝；被删除的触发器的文档保存在世界的 `.trash/triggers` 里，被其他触发器等待的触发器不能删除。

它适合需要综合多个世界部分的工作，例如：添加符合既有阵营的人物、寻找不完整连接、把一个前提拆成少量可选节拍，或检查私密知识是否交给了正确角色。只改一个明确字段时，视觉编辑器通常更快。

## 研究工具

世界、预设和世界书创作助手可以使用其他插件为所有人注册的工具，例如网络搜索或 MCP 服务器，这样“使用崩坏：星穹铁道的设定”就可以查询，而不必猜测。默认情况下它们没有任何这类工具。请在**设置 → 角色扮演 → 创作助手的工具**中勾选每个助手可以使用的工具；更改在助手的下一步生效，已经打开的对话也一样。助手只能看到为它勾选的工具，所以你为其他用途配置的工具不会到达它那里。勾选的工具会直接运行，不会每次都征求你的同意，并且以其插件拥有的权限执行，所以只勾选你放心让助手使用的工具。同一个列表还有第四项，**游戏中的世界作者**：为故事补充所需地点、人物或物品的辅助智能体，它可以先查询再动笔（例如故事去到的真实地点、某个作品里的生物），并多得到几次调用机会来使用你勾选的工具。会话医生永远没有任何工具。游戏中程序启动的其他辅助智能体（导入步骤、记录员和建议生成的助手）只有它们自己的工具；主持人、角色和记录员的工具由故事自己的“工具”开关决定。

也可以只给某一个助手配置工具：在配置档的配置里，把 MCP 服务器加载到该助手的预设中，这样它对其他一切都不可见。

## 批准

每项修改都必须通过 DSH 的批准流程。拒绝不会改变文件；批准后工具会验证提议文档并原子写入，错误会返回对话供助手修正。

请描述目标，而不是文件操作，例如：

- “在市政厅下添加一间上锁的档案室，并连接到记录室。”
- “让 Mara 单方面不信任 Elias，但不要改变 Elias 对她的看法。”
- “检查第一条剧情，降低它主动推进的压力。”

使用共享的**世界**页签检查结果。创作对话和编辑器操作同一个工作区目录。

## 高效工作流程

1. 说明期望结果，以及哪些事实不得改变。
2. 要求助手先检查相关世界元素，再提出修改。
3. 审查每项批准请求，特别关注 ID、关系、位置与私密知识。
4. 在世界页签中结合上下文检查结果。
5. 继续扩展前，先运行一段短会话。

好的请求给出约束，但不必规定存储格式。例如：“给档案室添加两个入口。一个需要黄铜钥匙，另一个无需钥匙但风险很高。”或“给信托会一个今晚可执行的目标，并说明他们为何不报警。”

避免一次修改就要求完整世界。较小的批准步骤更容易审查，验证错误也更清楚；世界变得拥挤之前，你还有机会纠正方向。

## 同时编辑

创作对话与视觉编辑器指向同一批文件，但两者都不是多人协作文档编辑器。完成并检查一次助手修改后，再进行重叠的手工编辑。若文件在 DSH 外被修改，请刷新编辑器后继续。

助手修改的是作者世界，不是活动会话数据库。已经开始的故事应通过该会话的世界页签进行有意修改。
