本页梳理与本套件相近的项目：角色扮演前端、跑团与叙事工具、记忆插件、数字人格项目、同人世界平台和商业陪伴应用。每个项目记录它的设计做法和用户的反馈，再与本套件目前的做法对比。

## 阅读说明

- **我们研究设计，不抄代码。** 每个条目只依据对外公开的行为（文档、README、公开的 issue、文章）。这里没有使用这些项目的任何源码、提示词原文、角色卡或素材。其中一些项目的许可证不允许在本项目中复用；这次调研的目的是了解问题所在，而不是借用它们的答案。
- **社区反馈是二手信息。** 抱怨来自公开的 issue、插件 FAQ 和文章。issue 数量和单个用户的说法都只是弱信号，文中已标明。厂商自己的说法标为“厂商宣称”。
- **有时效，也不完整。** 调研于 2026 年 11 月进行。很多项目规模小、变化快；中文论坛很难被检索，Reddit 和个别论坛无法读取，所以这些声音偏少。B 站只能搜到视频标题，看不到评论。
- **本页不含计划。** 这里只有对比。要不要做、做什么，另行决定。

## 角色扮演前端与跑团工具

| 项目 | 是什么 | 值得注意的设计 |
|---|---|---|
| [SillyTavern](https://github.com/SillyTavern/SillyTavern) | 常用的角色扮演前端，也是本套件可导入的角色卡和预设格式的来源。 | 记忆和向量召回是可选扩展，不是默认。世界书按关键词在最近少量消息里匹配，并争抢令牌预算。 |
| [Talemate](https://github.com/vegu-ai/talemate) | 带代理的故事与角色扮演引擎。 | 生成前有一道“视角”处理，记录每个角色感知到了这段文字的哪些内容，并有从关闭到彻底的力度预设。有可查看日志的决策模型。设置助手可以解释并修改选项。 |
| [Luker](https://luker.cups.moe/) | SillyTavern 的分支。 | 生成前由一组代理先运行，结果绑定到触发它的那条消息，所以重新生成可以复用；有一种模式保持单个不断增长的对话，使服务端的提示缓存不失效。技能是按需加载的知识包，作用域可以是全局、预设或角色，并随角色卡导出。回复中写入的变量变成逐消息的操作日志，因此滑动和删除可以回滚。诊断按钮会打开预填了某次编排运行的编辑器，请求检查器显示每次生成的令牌用量。 |
| [Project Lunar](https://github.com/horizonfps/project-lunar) | 世界模拟类角色扮演项目。 | “世界反应”步骤让屏幕之外的变化随故事经过的时间缩放：不到一小时几乎没有变化，一个月后可以发生大事。战斗没有数值表，按创意、连贯和上下文打分。 |
| [RisuAI](https://github.com/kwaroran/RisuAI) | 中文社区常用的角色扮演前端。 | 角色立绘可以随情绪标签切换。 |
| [Agnaistic](https://github.com/agnaistic/agnai) | 可自行部署的角色扮演前端。 | 因其多用户和托管模式而列入，没有挑出具体功能。 |
| [AI Dungeon](https://aidungeon.com/) | 托管的文字冒险服务。 | “故事卡片”在上下文出现其触发名称时注入世界事实。 |
| 跑团类语言模型主持人 | 研究与爱好者项目（[例如](https://arxiv.org/html/2409.06949v1)）。 | 应对偏离规则的常见办法，是给模型骰子和状态更新的函数，而不是让它自己计算。 |

## 记忆与状态插件（以中文社区为主）

| 项目 | 设计要点 |
|---|---|
| [Smart-Memory](https://github.com/senjinthedragon/Smart-Memory) | 每个角色的知识有五种状态（知道、怀疑、错误地相信、不知道、隐瞒）；记忆标注是否为转述；用图显示哪条记忆取代了哪条。它自己的文档列出了已知缺口：编辑消息不会更新由它提取的记忆，分支不会回滚长期记忆，重复运行会产生近似重复的条目。 |
| [st-memory-enhancement](https://github.com/muyoou/st-memory-enhancement) | 把记忆做成可见、可编辑的表格，模板可以分享。 |
| [MVU (MagVarUpdate)](https://github.com/MagicalAstrogy/MagVarUpdate) | 模型在回复里写更新块，作者编写的 HTML 状态栏显示由此得到的变量。 |
| [Tavern Helper](https://n0vi028.github.io/JS-Slash-Runner-Doc/) | 允许角色卡在聊天里运行脚本和前端代码，包括状态栏。它的 FAQ 几乎是这类显示如何出问题的目录。 |

## 数字人格与陪伴机器人项目

| 项目 | 设计要点 |
|---|---|
| [InkSpirit](https://github.com/Airliny/InkSpirit) | 把人格拆成灵魂（身份、记忆、性格、情绪、关系）、大脑（任意模型）和身体（立绘、Live2D 或 VRM）。性格和关系的变化以事件溯源方式记录，因此可以追查原因；导入存档时用连续性指纹校验；主动行为有每日额度和勿扰处理。 |
| [immortal-skill](https://github.com/agenmod/immortal-skill) | 从聊天记录按四个维度提炼人格，按来源给每条事实分级（原话、物证、印象），把相互矛盾的内容放在单独的文件里而不强行解决。对不同对象（本人、同事、已故亲人、前任）有各自的同意规则。 |
| [MaiBot](https://github.com/Mai-with-u/MaiBot) | 群聊机器人，目标是“更像活人”而不是“更好”，口语化，并会判断何时开口。 |
| [AIRI](https://github.com/moeru-ai/airi) 与 [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) | 语音陪伴：支持打断，Live2D 表情由情绪映射，会主动说话，能看屏幕。两者都处于早期，记忆缺失或仍在开发。 |

## 同人与授权世界

| 项目 | 设计要点 |
|---|---|
| [Mantella](https://github.com/art-from-the-machine/Mantella) | 为《上古卷轴 5》的角色提供对话，依据采用相同方式共享许可的维基文章生成，并能感知游戏内事件。 |
| [Hidden Door](https://www.hiddendoor.co/platform) | 面向授权世界的平台。按其自述（厂商宣称），每个计划好的情节在玩家看到之前都会对照原作设定检查；起始知识与游戏中揭晓的秘密分开存放；分级和死亡设定按世界设置；大量窄任务由小型微调模型完成。 |
| 迪士尼与 Character.AI | 2025 年迪士尼发出停止侵权函，Character.AI 下架了迪士尼角色（[Axios](https://www.axios.com/2025/09/30/disney-characterai-cease-desist)、[NBC](https://www.nbcnews.com/business/business-news/characterai-removes-disney-characters-from-platform-after-request-rcna234827)）。平台此前把这些角色形容为可互动的同人作品。 |

## 商业陪伴应用

[Character.AI](https://character.ai/)、[Kindroid](https://kindroid.ai/)、[Replika](https://replika.com/) 以及国内的星野、猫箱、筑梦岛都是闭源产品，只能依据它们公开的行为和媒体报道来评估。

- **固定记忆。** Kindroid 有用户可编辑的“关键记忆”，模型每轮都会看到（[介绍](https://aicompanionpick.com/ai-companion-memory-kindroid-nomi-replika-long-term-2026)）。
- **留存。** 国内媒体报道，筑梦岛和星野的三日留存低于 20%，用户与单个角色相处大约五到七天（[凤凰网](https://tech.ifeng.com/c/8kfDCmQkqSO)）。一篇文章说，因为缺少剧情引导，角色在一两千轮之后就被“聊透”了。另一篇说，主动消息（“活人感”）是玩家看重的（[虎嗅](https://www.huxiu.com/article/4840220.html)）。
- **角色一致性。** 据报道，猫箱的角色在模型降级后行为发生变化（[界面新闻](https://www.jiemian.com/article/12484390.html)）。

## 用户反馈

按主题归类，并注明来源。

**记忆缺失、浅薄或悄悄失效。**
SillyTavern 默认不带记忆，世界书条目在争不过令牌预算时没有任何可见提示地失效（[roborhythms](https://www.roborhythms.com/sillytavern-memory/)）。AI Dungeon 的故事卡片在名字没被提到时不会加载，上下文紧张时会被丢掉（[AI Dungeon 帮助](https://help.aidungeon.com/faq/why-does-the-ai-forget-or-mix-things-up)）。据报道，Character.AI 会忘记玩家的个人信息并重复提问（[roborhythms](https://www.roborhythms.com/why-character-ai-memory-broken/)）。

**记忆记到了错误的人身上。**
MaiBot 的 issue 里有多起群聊中事实被记到错误说话人的报告。据报道，Replika 曾连续数月把朋友的婚礼记成用户本人的（[来源](https://cave.co.nl/blog/replika-alternatives/)）。两个互不相干的产品，同样的失败。

**自动记忆杂乱，且不跟随编辑和分支。**
Smart-Memory 自己记录了上述缺口。一位用户的说法（未经核实）是提取出六百多条，手工删到三百条左右。

**玩家想锁定不该变的内容。**
记忆表格插件有用户要求“表格锁”，防止模型覆盖受保护的数据。Kindroid 的关键记忆和 Hidden Door 的版权方设定锁，从不同方向回应同一需求。

**严格格式很脆弱。**
MVU 讨论最多的议题是要求一个宽松版本。Tavern Helper 的 FAQ 列出状态栏空白或消失的许多原因：正则顺序、渲染深度限制、安全过滤截断输出、中转商换成较弱的模型。记忆表格插件则有表格变大后填写失败、表格与聊天对不上的报告。

**套话与出戏。**
中文玩家抱怨同样的小动作在回复间反复出现，以及角色失去自己的口吻，尤其在语音通话和更换模型之后。玩家的应对办法是重说、手改回复。

**新鲜感耗尽。**
上面的留存数字和“聊透了”的说法，指向的是剧情引导，而不是记忆。

**角色消失。**
角色会因审核被下架，或随创作者被收购而消失。猫箱的收购引发了一波怀念帖，迪士尼案例则表明法律途径同样会造成这种损失。

**限额与成本。**
筑梦岛对免费聊天每日 100 条的限制引来强烈反对。Luker 增加了请求检查器，因为 SillyTavern 没有系统地展示令牌用量。

**安装与数据安全。**
Talemate 最热的议题是安装。SillyTavern 有报告称客户端会用开场白覆盖一段完好的聊天（[#5941](https://github.com/SillyTavern/SillyTavern/issues)）。

**被要求的功能。**
每个角色用不同模型（SillyTavern [#3139](https://github.com/SillyTavern/SillyTavern/issues)）、一个聊天挂多本世界书、图片世界书、工具调用和移动端布局。

**跑团中的偏离。**
语言模型主持人在长战斗中会忘记骰子规则；一位 B 站玩家说，每次角色死亡后都要重新发送规则书提示词。

## 本套件目前的对比

下表描述本套件当前的行为，而不是意图。

| 主题 | 其他项目 | 本套件 |
|---|---|---|
| 角色知道什么 | 视角处理（Talemate）；五种知识状态（Smart-Memory） | 缺少连接就表示角色不知道某物存在。事件不可变，感知按角色分开。知识只有“有”或“无”；“怀疑”“错误地相信”“隐瞒”不是单独的状态。信念单独保存，可以修订。 |
| 状态回滚 | 逐消息操作日志（Luker）；Smart-Memory 列为缺口 | 每回合保存整个故事的快照。回退、切换、重新生成和分支会让状态与对话一起还原。 |
| 骰子与规则 | 给模型函数（跑团研究） | 由代码掷骰并读取结果。世界自行定义检定，主持人不解读数字。 |
| 状态显示 | 模型写更新块和 HTML（MVU、Tavern Helper） | 数值记录在故事状态里，每回合后判定；界面包读取玩家视图。有状态页。尚未做出由数值绘制显示的界面包。 |
| 固定或锁定的事实 | 关键记忆（Kindroid）、表格锁、设定锁（Hidden Door） | 作者写的背景资料不能被记录员改写。故事自己的记录没有逐条固定的功能。 |
| 编辑回复 | 手改回复作为引导手段 | 有重新生成和回退。不提供原地编辑已送出的回复。 |
| 重复 | 对套话的抱怨 | 有一道关口，对照最近回合找出重复的句子，并判断这次重复是否有意。它不跟踪精确句子之外反复出现的动作或措辞。 |
| 每个角色用不同模型 | 被要求的功能 | 角色、背景角色、记录员、建议和创作助手都可以分别指定模型。 |
| 成本与诊断 | 请求检查器和诊断按钮（Luker） | 每回合的追踪，记录各代理被告知什么、做了什么，以及每回合的令牌用量；可选地把追踪发到 Langfuse。会话医生是单独的聊天，不能从某个回合直接打开。 |
| 力度 | 从关闭到彻底的预设（Talemate） | 决策、反思、关口和后台任务各有许多单独的设置。 |
| 屏幕外的变化 | 随经过的时间缩放（Project Lunar） | 角色的日程会追赶到当前时间，到期的约定在场外处理，势力有策略师，玩家不在时故事也可以继续。 |
| 表情与语音 | 随情绪变化的立绘和语音（RisuAI、AIRI、Open-LLM-VTuber） | 情绪作为数值记录，可生成立绘和场景图，支持语音。立绘不随情绪变化。 |
| 同人与授权世界 | 基于维基的角色（Mantella）、设定检查（Hidden Door） | 世界是本地文件；角色可从角色卡导入；目录让人们分享世界。没有维基导入器。目录是一套协议而不是一项服务：谁运营目录，谁决定它的内容政策，本项目不设任何限制。 |
| 所有权 | 托管服务上的角色会消失 | 角色和世界是本地文件，归使用者所有。 |
