---
title: 回合编排
---

一条玩家消息可在最终叙述前产生多轮角色行动。这是一套智能体循环，而不是固定流水线：GM 决定哪些角色需要作出选择，以及后果是否需要另一轮；确定性的边界则限制可以跳过、重复或提交的操作。创造性判断交给智能体，重要状态变化必须经过明确工具与验证。

1. GM 读取玩家行动、当前场景、相关记录、节奏提示和规则。
2. 它激活此刻需要作出决定的角色。
3. 每个角色智能体获得稳定人格、当前处境、自身关系、已知实体与回忆。
4. GM 把角色意图解析为结果和状态变化。
5. 它可以再开始一轮，或交付叙述。
6. 已交付的内容记录为一个玩家回合，并安排后台工作。

角色输出采用结构化格式：意图、可选发言和投入程度。高投入但失败的行动可以带着第一次结果重试一次。同一玩家回合内的后续轮会看到之前各轮。

GM 不能在解决必要角色之前直接叙述重大结果。引擎会提示下一步必须调用的操作，拒绝对同一局面的重复激活，并检查行动是否发生在玩家实际所在地点。这些门控减少矛盾，但不会规定叙述文字。

## 为什么角色要独立运行

角色智能体看到的是自身人格、当前处境、关系、已知实体和回忆，而不是完整世界数据库。独立决策让视角真正成为边界，而不只是一条埋在全知提示词中的要求。害怕的目击者可以隐瞒信息，陌生人可以认不出地点，两个人也可以对同一事件产生不同理解。

角色以结构化意图把结果交还 GM。GM 负责判定成败、执行世界规则并组织玩家最终看到的内容。角色智能体不会直接写入对话或数据库。

GM、角色、记录员、世界作者、编年者和图片作者分别拥有不同提示词与工具。子智能体是一次性的；持久身份和记忆来自角色扮演状态，而不是长期私有聊天记录。

## 边界与失败恢复

引擎限制轮数、参与角色数、工具调用次数和输出 token，避免自主场景无限运行。角色数和轮数限制场景广度，工具上限阻止助手无限搜索，输出预算则避免本地模型在需要结构化答案时生成过长散文。

提醒或一次重试可以恢复未完成的助手调用，但反复发生的提供方失败会显示在活动记录中，不会被伪装成故事事件。

## 前台与后台工作

交付给玩家的回合属于前台工作。记录、行动建议、图片、语音准备、上下文压缩和离场决策可以根据设置与可用提供方随后运行。它们仍受同一套边界限制；活动列表会显示哪个助手运行、耗时以及是否失败。

聊天空闲时不会有自主循环继续运行。后台故事行动只在玩家消息推进会话时被考虑；把浏览器标签留在后台既不会消耗 token，也不会让世界自行前进。

稳定人格和工具声明位于变化的场景数据之前，有利于在请求之间复用模型前缀缓存。对玩家来说，实际要求很简单：描述角色要做什么，而不是指定系统应生成怎样的逐字剧本。
