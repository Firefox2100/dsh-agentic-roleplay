---
title: 故事时间、日程与节奏
---

模拟模式中，时间依据 GM 记录的轮次时长和显式跳时前进；现实模式跟随配置时区的墙上时钟。拥有独立日期的模拟故事不能再切回现实时间。

记忆年龄、截止时间、日程和离场行动都使用故事时间，而不是回合数或现实耗时。大量回合可以只经历一分钟，一次跳时也可以跨越数日。

日程只提供角色通常所在位置与活动，承诺、中断和剧情事件都可覆盖它。如果通往时间窗所指地点的每一段通路都标有路程时间，不在你身边的角色会先处于“在前往某地的路上”，直到时间窗开始后过了这么久才算到达；通路没有标时间则立即到达。回合结束后，有限数量的离场角色可处理到期承诺或截止事项。同一个约定的几个人会依次决定，后者会被告知谁已决定前来，因此碰面发生在人与人之间（设置 `offstage.joint`）。组织也会自行行动：你发送消息后，最多 `factions.perTurn` 个手握目标、且距上次决策已过 `factions.everyDays` 天故事时间的组织各自决定做一件具体的事。这会改变它们的状态与目标，并记录为一件在有人被告知之前无角色知晓的行动。

作者可按星期、月份、每年或一次性日期、日期区间、每月第几天、季节或世界声明的节日限制日程，也可用排除项确定地表达“工作日，但建城纪念日除外”。列表中第一个适合当天的时间窗生效，所以只改某一天，就是在平常的时间窗前面放一个用 `on` 指定日期的时间窗（例如 `"on": ["1912-10-05"]`）。游玩中，当故事确立某个角色在某一天的安排不同（卧病在床、外出办事）时，记录员用 `routine_exceptions` 做同样的事：在日程前面放一个只属于那一天的时间窗，其他日子不受影响；对同一天再次设置会替换它。季节依据世界 `calendar.json` 中的半球计算，详见[日历与日期规则](../world-format/calendar)。

剧情为 GM 提供可选节拍与压力；触发器则保证条件成立时执行确定反应。前者可调整或推迟，后者适合作者要求每次一致发生的变化。
