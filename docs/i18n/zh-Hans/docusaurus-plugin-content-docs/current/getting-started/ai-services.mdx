---
title: 配置 AI 服务
---

角色扮演始终需要 DSH 语言模型路由。其他能力会在运行时按是否存在来启用。

| 能力 | 用途 | 未配置时 |
| --- | --- | --- |
| 语言模型 | GM、角色、记录员、创作与摘要 | 无法进行会话 |
| 嵌入 | 语义记忆、设定和图片检索 | 仍使用关键词和显式线索 |
| 重排序 | 精排候选记忆 | 直接采用检索分数 |
| 图片生成 | 肖像和场景插图 | 图片操作明确报告未配置 |
| TTS | 旁白和角色语音 | 不提供播放或明确失败 |
| STT | 录音与实时语音输入 | 正常使用文字输入 |

通过 [DSH AI Providers](https://firefox2100.github.io/dsh-ai-providers/zh-Hans/docs/intro) 安装和配置服务。在**设置 → Providers**中登记每个端点和凭据引用，然后在各服务页（**语言模型**、**Embedding**、**重排序**、**语音合成**、**语音识别**、**图像生成**）中选择提供方、连接和模型。

通过 DSH AI Providers 使用语言模型时，请按照其配置档案说明操作：禁用 DSH 默认的 `@deepseek-ai/dsh-llm-pi-ai` 适配器和 `ui-settings-models` 页面，但保留核心 `llm` 服务。提供方是否共存属于配置档案层面的选择，角色扮演套件不会自动修改它。

本地推理应配置并发限制，使共用 GPU 的前台请求优先于向量索引等后台工作。

### 模型建议

- GM 需要良好的指令遵循和工具调用能力。
- 如果 DSH 配置支持分别路由，角色智能体可以使用更快的模型。
- 图片理解需要由提供方声明为支持图片输入的模型。
- 自动上下文限制依赖正确的模型上下文长度元数据。

最简单的起点是用一个能力足够的模型承担全部角色。之后可以在**对话设置 → 模型**中为角色、记录员、行动建议、世界创作和剧情工作分配更快或成本更低的路由。某项留空时会继续使用对话所选模型。

一次智能体回合可能产生多次模型调用：GM 可以召集多个角色，记录员会保存结果，之后还可能生成摘要、建议或图片。如果延迟或本地推理容量有限，请先使用**快速预设**，再按需要逐项增加深度。参见[会话设置](../playing/settings)。

### 推荐配置顺序

1. 开始会话前，先验证一个支持工具调用的语言模型。
2. 需要语义记忆和设定检索时再添加嵌入。
3. 只有较宽的候选检索集确实需要精排时才添加重排序。
4. 根据实际使用的呈现功能添加图片、TTS 和 STT 提供方。

能力调用失败不会破坏故事。可选后台工作会重试或省略，必要的回合操作则会明确显示失败。
