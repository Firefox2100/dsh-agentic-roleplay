---
title: 代码强制的与仅作建议的
description: 故事中哪些规则由代码检查，哪些交给模型，以及界线在哪里。
---

故事由模型运行，所以有些规则由代码把关，有些只是写在提示词里。本页把两类都列出来，方便世界作者和维护者知道哪些可以依赖。
“强制”指无论模型怎么说，代码都会拒绝或纠正结果；“建议”指提示词或简报提出了要求，但没有任何检查。

## 代码强制

| 方面 | 保证的内容 |
|---|---|
| 输出 | 角色说过的每句话在叙述中恰好出现一次，不得凭空添加，并按回合轮次的顺序排列。第三次仍不合格时由代码修正并标记为已修复。 |
| 语言 | 叙述和角色回答若使用了与对话语言不同的文字，或在中文文本中留有小写英文单词，会被拒绝并指明应使用的语言。只区分英文和中文；过短的文本放行。 |
| 认知 | 角色只会看到自己知道的内容：没有关联边就表示不知道该实体。有意的移动只能经过已知的目的地和已知的有向出口。 |
| 移动 | 上锁或被堵住的出口会拒绝移动并指明是哪条出口；只有故事自身的裁定（`ignore_exits`）可以越过。 |
| 物品 | 物品必须够得着（未隐藏、未关闭、未上锁），钥匙必须在手中，可穿戴物必须符合自己的栏位及其容量，容器不能装自己。 |
| 骰子 | 由代码掷骰并读取档位，游戏主持人从不解读数字。当判断标记为不确定且该智能体有骰子时，必须先有一次掷骰才能激活角色；掷过骰的角色的结果必须引用该次掷骰。 |
| 记忆 | 已封存的事件不能修改或删除。记录编辑要么整体生效，要么完全不生效。开启 `memory.verify` 后，记录员读回上一次编辑之前不能结束。 |
| 回合 | 每个对话同一时间只有一个回合；每回合最多 `maxRounds` 轮、每轮最多 `maxCharacters` 个角色；输出通过 `narrate` 交付，回合随之结束。 |
| 输入 | 游戏主持人先用 `judge_action` 判断普通输入。被拒绝时只是玩家角色的一轮失败，不会跳过回合。 |
| 创作 | 每回合最多 `authoring.perTurn` 件新造之物；已被占用的名字或别名会被拒绝；新造的地点必须接通，新造的角色必须有位置。只有世界作者能造东西。 |
| 工具 | 可选工具和其他插件的工具默认关闭，需为对应类型的智能体开启。辅助智能体用完预算后工具会被撤走，重复的失败调用会被拒绝。 |
| 文件 | 世界、预设、界面包和开始请求在创建任何东西之前先按格式检查，并报告所有问题。界面包在沙盒中运行，只能看到玩家视图。 |
| 时间 | 模拟时间只随轮次和 `advance_time` 推进；真实时间跟随挂钟，不能跳过。一轮至少耗时玩家的行程。 |

## 仅作建议

| 方面 | 交给模型的内容 |
|---|---|
| 世界规则 | 世界的自由文本 `rules` 由游戏主持人通过 `judge_action` 判断。代码保证先做判断，但不决定结论。 |
| 关系 | 熟悉度、信任、好感和紧张度只出现在简报里，没有代码使用这些数值。 |
| 谁感知到 | 简报会显示当时谁在哪里；哪些角色感知到了某个事件，由记录员在写入时决定。 |
| 误记 | 角色是否记错，由写入者在写入时按对话的 `flaky` 设置决定。 |
| 约定 | 约定是否履行，代码从不判断，由角色和记录员决定。 |
| 节拍 | 触发器的节拍只是对游戏主持人的软性提示，不采纳就会失效；提示（cue）告知角色，角色可以不理会。 |
| 路程 | 出口的路程时间计入玩家的行程和例行移动；其他角色的移动不会因此延迟。 |
| 合理性 | 随身物品没有重量或容量限制，由模型判断是否合理。 |
| 角色思考 | `thought` 字段声明为必填但并未强制，其在工具模式中的顺序后端也只是部分遵守。 |
| 建议 | 只检查数量、长度和重复，不检查是否有意义。建议写手失败时，会改为显示由故事自身数据生成的建议（在场的人、通畅的出口、可见的物品）。 |
| 导入的文本 | 输入和导入内容受信任；不会防范藏在卡片或预设里的指令。 |
