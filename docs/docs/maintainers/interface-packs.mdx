For the author's view see [Interface packs](../authoring/interface-packs) and the [format reference](../reference/interface-pack-format). This page is for changing the feature itself.

## Invariants

- **No pack code runs in the DSH page.** Scripts run only in `<iframe sandbox="allow-scripts">`, without `allow-same-origin`. The page puts into itself only a theme override layer and a checked stylesheet.
- **The player view is a whitelist.** It is built field by field from what the player's character could know. A field is added to `PlayerView` only with a line in the leak test that puts a secret in its source.
- **Packs are read afresh.** Nothing about a pack is cached beyond one request; the client polls and reloads when the revision moves.
- **A pack with any problem is not used.** Start refuses a world whose packs have problems; a story shows no pack until its copy is fixed.
- **Nothing here writes story state.** A surface can send words as the player or fill the input box; the model stays the game master.
- **Prompt injection and everything that changes what a model is told are out of scope.**

## The preview and the packs that ship

`GET /worlds/interface?id=` lists a world's packs with what each holds and its problems (`InterfaceService.worldPacks`); `GET /worlds/interface/preview?id=&pack=` answers with the pack as a story would load it and the view it would be given (`preview`). The view comes from `previewViewOf`: the world's files are loaded as a start loads them, a story is made in memory (`:memory:` store, nothing written), the first playable character is the player, they look around as at the start of a turn, and `playerViewOf` reads it, with three sample suggestions. A frame key is made per world and pack and stays the same for the life of the host; the frame route serves such a key with the id `preview:<key>`, so the files are read from the world folder and nothing is copied. The editor gives the frame a backend that has no turns and keeps what the pack stores in memory.

The packs in `packs/` (today `scene`) are put into `<root>/ui/` at startup if the folder is missing (`installFirstPartyPacks`); a pack with a tab surface must not ship there, because any pack with a tab makes the Interface tab appear for every story (`availability`).

## Flow

1. **Start.** `startSession` calls `copyWorldPacks`, which checks every pack of the world and copies them to `<session>/ui/`; problems refuse the start (422). A branch copies the session's packs (`inheritPacks`).
2. **Choice.** `activePack` takes the setting `interface.pack`: empty is the story's first pack, `none` is off, a name is the story's pack or else one of the root's.
3. **Page.** The client asks `GET /sessions/interface` (the description with the checked skin and theme), polls `GET /sessions/interface/view` with the last revision, and mounts a frame per surface. One `PackDock` serves `hud`, `dock` and `opening` as slots of `conversation.input.dock`; the `hud` one also applies the skin and the theme and mounts the backdrop. Polls are shared per story.
4. **Bridge.** The frame posts requests; the page answers through `Bridge` (permissions, limits) and the host routes (view, history, storage).

## Routes

All under `/roleplay-api`.

| Route | Purpose |
|---|---|
| `GET /sessions/interface?id=` | The pack in use, with the problems if there is none |
| `GET /sessions/interface/view?id=&revision=` | The player view, or `{ unchanged: true }` |
| `GET /sessions/interface/history?id=&limit=` | The turns so far |
| `GET /sessions/interface/status?id=` | The setting, the pack in use, the packs available, the world's packs against the copies |
| `POST /sessions/interface/sync?id=` | Bring the world's packs in |
| `POST /sessions/interface/storage?id=` | Get, set or remove a value of the pack |
| `GET /interface/availability` | Whether any pack has a tab |
| `GET /sessions/interface/pack/<id>/<file>` | A pack file for the page (skin urls), with the login |
| `GET /sessions/interface/frame/<key>/<file>` | A pack file for a surface, **without a login** |

### Why the frame route has no login

A sandboxed frame has an opaque origin, so it cannot use the authenticated pack route for its document or subresources. All of the frame's files are therefore served read-only under a key in the path, which also makes relative addresses work. The key is 24 random bytes per story, made when the host starts and given only by the authenticated description route. It opens only the currently active pack's files and never the player view, which travels only over `postMessage`. The API handler skips the login check for exactly `GET` on this prefix; `tests/host/http/api.spec.ts` checks that every other route and method still needs it.

Every pack file is served with `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'self' 'unsafe-inline' 'unsafe-eval' 'wasm-unsafe-eval'; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self' data:; media-src 'self' data: blob:; connect-src 'self'; frame-src 'self'; form-action 'none'; base-uri 'self'`, `nosniff` and `no-referrer`; files served on the frame route also carry `Access-Control-Allow-Origin: *`, because a frame without an origin reads its own files cross-origin.

Why the policy is wide inside the frame: the missing origin keeps code out of the host page, cookies and storage, while fetch directives limit ordinary resource loads to the pack. Restricting `eval`, workers or WebAssembly would not constrain what the pack can compute and would break ordinary libraries. `connect-src 'self'` lets a page `fetch('data.json')`; a request to the authenticated DSH API carries no login and its answer cannot be read. Checked in a real browser frame: own files, workers, WebAssembly, `eval`, WebGL and canvas work; external fetch, images and WebSockets, the host API, the parent page, storage, cookies, popups and top navigation do not. **Self-navigation remains possible and can carry data in its URL; no shipping browser supports a CSP directive that prevents it. Packs are therefore trusted input.** The `sandbox` directive is in the header as well as on the frame, so opening a frame address directly still applies the document restrictions. HTML pages get the bridge script first.

## The bridge

`frame.ts` holds the script a surface gets (plain ES5, only posts messages). `client/interface/bridge.ts` answers: the action list from the manifest, 20 requests a second, one `say` per turn (or 30 seconds), 2000 characters of words, limits on history. The page ignores a message whose source is not the frame's window, or whose shape is unknown. `parseFrameMessage` is the only reader of what comes from a frame.

**Never name a prop injected into a dock `input`.** DSH's own dock props have one, and it shadowed ours (found live: `rp.say` failed with "input.say is not a function"). Ours is `frameInput`.

## The sidebar page

`client/interface/SidebarPage.tsx` and the registration in `index.ts` add a tab type (`roleplay-pack`, id `@dsh-agentic-roleplay/core/interface-sidebar`, `keepMounted`) to DSH's right sidebar through `sidebarRightTabs`, a guide card under `sidebar.right.tab.guide.entry` and the body under `sidebar.right.pane.tab`. The card is our own copy of the capsule look and renders nothing for a story whose pack has no `sidebar` page, so the guide of an ordinary chat is unchanged. The body is a bar (a Back button that calls `openTab('guide', { replaceTab: true })`) over a `PackFrame` that fills the rest. `rp.open` goes through `PackFrame`'s `FrameInput.open`, which calls `sidebarRight.openTab` or activates the pack's tab view.

## The skin check

`checkSkin` is a small tokenizer and rule walker, not a CSS engine. It keeps `@media`, `@supports`, `@keyframes`, `@font-face`, requires `[data-rp...]` standing on its own (outside a function) in every compound selector, refuses nesting and escapes outside strings, and rewrites each `url()` to the file route. When extending it, add a refusal test before an allowance.

## The backdrop

The conversation paints an opaque root and a scrolling body above anything under it, so a layer cannot sit behind the text by `z-index` alone. `client/interface/backdrop.ts` finds the body (the parent of the element whose class contains `_scrollBody`, from the dock upward), inserts a layer as its first child and lifts the scrolling body above it with the attribute `data-rp-lifted` (`position: relative; z-index: 1`). DSH's fade above the composer covers the lower part. If the structure is not found there is no backdrop and a console warning.

## Authoring

The world-authoring preset mounts DSH's `tool-fs` (row `tool-fs` in the bundle patch). `registerPackJail` registers, first in `tools/pre-execute`, a listener that limits `read`, `write` and `edit` in authoring chats to ordinary text files of `<world>/ui/<pack>/` (at most 200 KB a call), refuses any symbolic-link component, refuses writes during an import review, calls the rest of the chain, and turns only a plain allow into the plugin's own ask; a later listener's deny or ask stands. `tests/host/authoring/pack-jail-runtime.spec.ts` runs this in DSH's real tool runtime, and fails if the jail is registered without `prepend`. The plugin's own tools are `world_pack_guide`, `list_world_packs`, `check_world_pack` and `delete_world_pack_file` (DSH's file tools cannot delete).

Paths are given to the model relative to the chat's folder; a long absolute path was mistyped by the model in the first live try. The refusal text tells it to stop and report, because it otherwise retries other paths and `sandbox_permissions`.

## What to check when DSH changes

| Touchpoint | Check |
|---|---|
| Slot `conversation.input.dock` and its props | Our injected names do not collide; order values 1, 3 and 20 still sit where intended |
| Slot `conversation.view` and `uiConversation.views` | The tab registers after a late `availability` answer |
| `sidebarRightTabs.register`, the slots `sidebar.right.tab.guide.entry`, `sidebar.right.pane.tab`, `openTab(kind, { replaceTab })` | The entry appears next to the others, the page opens, Back returns to the guide |
| Theme service `overrideTokens` (looked up with `scope.get('theme')`) | Still there, still takes `{ light, dark }` pairs |
| The body attribute `data-ds-dark-theme` | Still marks dark; the frame's scheme follows it |
| Class fragments `_scrollBody`, `_composerSeat` | The backdrop and any measuring still find them (`tests/support/dsh-contract.spec.ts` checks `_scrollBody` in the installed conversation bundle) |
| Tools `read`, `write`, `edit` with `file_path` | Names and argument names the jail reads; `exec.agent.session.header.cwd` |
| `tools/pre-execute` with `{ prepend: true }` | The runtime test still passes |
| `react-dom` as an external module | Typed by `src/client/react-dom.d.ts`; the shell must still provide it |

## Testing

Unit and integration tests cover the pack check, the skin check, the player view (a secret in every source), the routes (including the unauthenticated frame route and the sync), the bridge, the backdrop's lookup, the jail and the authoring tools. What no test covers is seen in a browser: load a story with the example pack, check the strip, dock, opening card, backdrop and tab in light and dark, edit a file and see it follow, break a skin and see the report in Chat settings, change the world's pack and update the story, and have the assistant write a pack with the approvals.
